# Data inventory and selection

The September 2026 addition has been sorted under `data/useful/` and `data/non_useful/`. “Non useful” here means **do not use as an input or evaluation result for the repaired study**. Those files are preserved for lineage and historical comparison; nothing was deleted or rewritten. The directory `data/` remains Git ignored because the review records may contain user text and identifiers.

The two review files cover Levi’s and Macy’s records, across 104 and 108 product IDs respectively. Their `scaled_rating` maps stars 1–5 to −1, −0.5, 0, 0.5, 1. Approximately 5,968 and 2,796 repeated title/comment pairs occur within the files, so a deduplication audit matters before estimating text-model accuracy. Those counts detect exact repeated pairs, not all near-duplicates.

The useful folder holds **candidate source material**, not ready-to-run canonical inputs. The repaired pipeline expects the schemas in [the data contract](data-contract.md), including exact `published_at` and `available_at` timestamps and a verified product mapping. Do not manufacture weekly timestamps from rounded “months ago” values. If the source scrape and collection date cannot be recovered, the reviews remain suitable only for a limited text/rating exercise; a new dated review collection is needed for a time-correct forecasting study.

## Product and time alignment checks

- The 505 Trends target is weekly from 2020-04 through 2025-04. The merged tables are monthly and mostly contain one February snapshot per year before 2024, so they cannot be joined as a complete weekly review history.
- The merged v3 table has 141 product IDs. Its name-based “505” subset has six IDs, including ID 41. The review files identify products by website and numeric ID; the numeric value is reused across websites and the later merged table has a different numbering system. The mapping from every review group to a product and its validity period still needs the upstream catalog. The tables actually **disagree** on ID 14: the early site-prefixed table names a 511 product, while the later integer-keyed table names a 311 product, and its review text often mentions 505. See [the product ID audit](product-mapping-audit.md); no review ID is approved as a 505 join.
- The old `Data Reader` export means the CSV and pickle are redundant formats, not independent evidence. The earlier 40-column pickle is a different intermediate table; preserve it only to trace the historical workflow.
- The latest review slice was never used as a confirmed temporal test in the visible old BERT notebook, despite having `predicted_label` values. Recover how those values were produced before interpreting them.

3. Collect or recover weekly collection coverage. Then run the scorer and backtest using the documented data contract. Until those timestamp fields exist, do not run the weekly sentiment comparison or report corrected real-data performance.
